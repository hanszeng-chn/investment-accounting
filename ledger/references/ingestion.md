# 导入与截图

先看来源范围和账本，优先稳定交易号。相同成交在截图/CSV/PDF出现时映射同事件ID幂等跳过。无编号时按账户、日期、类型、标的、金额、份额和顺序做相似候选，核对后复用已有ID；不同文件hash不是不同交易的证据。相同特征但确认两次成交时用allow_similar:true并注明依据。

用ledger.py source <file>归档取得source_id；视觉/读取工具抽成标准批次，存data_dir/exports/，再apply。日期/账户/方向/成交量模糊的写pending，已确定记录照常写入。

截图明确给出累计投入、转出、期初和净投入但与导出流水不符时，记录BASIS_CHECKPOINT校准截至日汇总，并用pending保留差额与未齐明细。不能造一笔未知日期转入凑平。截图总资产与旧估值冲突时用supersedes更正同日VALUATION，来源与原记录均保留。收益率列标题不完整或算法未知时只保留原图，不猜成简单损益率。

截图核对：业务日期而非截图日期、币种、委托还是成交、代码、买卖方向、成交份额、成交总额、费用、现金余额、累计还是增量。买卖只记BUY/SELL；银证转账才是CASH_FLOW。总资产记VALUATION，基金单位净值记quote，累计持仓记POSITION_OPEN。净到账额只有费用清楚才能反推不含费总额，否则pending。多渠道同标的先区分账户或明确汇总，不能让份额基线互相覆盖。

首次账户须有OPENING；仅有无起点交易时pending并询问起始数据。现金未知不填0；明确全部只有这些持仓且无现金时，才写CASH_BALANCE 0并确认完整覆盖。

## 长钱账本迁移

```sh
python3 <skill>/scripts/import_legacy.py --root <data_dir> --db <source.db>
```

SQLite只读，通过backup API归档含WAL的完整快照。保留资产、记录、操作ID，导入持仓与行情，不叠加多个旧备份。相同ID内容不同即停止，明确来源再更正。当前用户项目已有核验版本test-results/curve-fix-20261103/updated.db；后续以更新的手机导出做增量核对，不覆盖新记录。

其他Excel/CSV先识别行粒度、币种、资金流/总资产列；PDF提取和关键页视觉核对结合；图片直接视觉读取；自然语言相对日期转绝对日期。其他JSON/数据库编写只读适配器输出标准批次，不绕过apply。金额用Decimal/字符串，避免浮点损失。原始表和手机数据库不改。

## 有知有行增量对账

新版Excel可能后补早期业务日期的资金流，并更改原有估值。先比较业务日期、记录类型、原始创建时间，再比较金额；不能只按新文件行号生成ID（插入行会让后续行号变化）。同事实已有记录应关联复用，金额修改用supersedes保留旧值。卖出款已配对转入现金分类时，新导出的同额转出必须关联原CASH_FLOW，不再次入账。

后续先读取已解决pending和数据目录中归档的对账报告，不再次按旧导出恢复已经解决的缺口。原表日志加法与总资产不一致应单列估值问题；找到真实资金流后，不能继续以原来的资金流缺失理由屏蔽整个历史收益率。个人金额及证据仅保存在账本和报告中，不复制进技能模板。
